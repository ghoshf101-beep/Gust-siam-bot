- Defaults: service buttons = primary, Get Number / 2FA Online / Refer / Go to Proxy Bot = success, Support / Close = danger

# FEATURES (STRICT STEPS)

### Feature 1 — Join, Captcha, Language:
Step 1 → /start saves the user in `users`; a referral code in the payload sets `referrer_id` (ignore self-referral and existing users)
Step 2 → If the user is banned, send the editable banned text and stop; if maintenance mode is ON and the user is not an admin, send the editable maintenance text and stop
Step 3 → Check every active row in `channels` (type=force_join) with getChatMember; if any is not joined show Join buttons plus a Verify button
Step 4 → If `captcha_enabled` = 1, show the emoji captcha (6 inline emoji buttons, one correct); on success set `captcha_done` = 1
Step 5 → Show language choice (English / বাংলা), save in `users.lang`, then send the welcome message (optional photo, both from `texts`/`settings`) with the main menu built from the `buttons` table

### Feature 2 — Dynamic Menu, Buttons and Custom Pages (everything editable):
Step 1 → The main reply keyboard, inline menus and submenus are built ONLY from the `buttons` table
Step 2 → Each button has: label_en, label_bn, emoji, style, icon_custom_emoji_id, action_type (builtin / url / page / submenu / contact_admin), action_value, parent_id, row_no, position, is_active, admin_only, min_balance (optional)
Step 3 → Builtin actions: get_number, buy_proxy, traffic, twofa, search_otp, refer, profile, wallet, withdraw, leaderboard, language, support, close
Step 4 → `pages` table lets admin create unlimited custom pages (title, text_en, text_bn, optional photo_file_id, up to 6 inline buttons with label/url/style); any button can open a page
Step 5 → admin/buttons.php: add, edit, delete, duplicate, reorder up/down, move between rows and parents, pick color from a dropdown, hide/show, with a live preview of the keyboard; changes apply instantly with no restart

### Feature 3 — Get Number (service picker, API mode and Manual Pool mode):
Step 1 → User taps Get Number; send the editable text "Select a service:" with one active service per row (emoji + name, style primary) in admin order, and a final ❌ Close button (danger) that deletes the message
Step 2 → After a service is selected, show its active `ranges` (flag, country, range code) one per row with ⬅️ Back and ❌ Close; admin can hide any range or service
Step 3 → Number source per range is set by admin: `api` (use the provider's getnumber endpoint) or `pool` (take the oldest free row from `number_pool` and mark it assigned)
Step 4 → Save in `numbers` (status=active, expires_at from `number_expiry_minutes`) and send to the user with buttons: 🔄 Change Number, 🔎 Search OTP, ❌ Cancel
Step 5 → Enforce `max_active_numbers`, `cooldown_seconds`, and the per-service daily limit; cron auto-closes expired numbers and returns unused pool numbers to free if admin enabled "recycle"

### Feature 4 — Buy Proxy, Traffic and Support (admin controlled):
Step 1 → Buy Proxy sends the editable text "🌐 Buy Premium Proxy — Click the button below to buy high-speed proxies from our official Proxy Bot:" with a success-colored "Go to Proxy Bot" URL button (link editable) and a danger ❌ Close button
Step 2 → Traffic shows live service traffic/availability pulled from the provider `liveaccess` endpoint (cached `liveaccess_cache_seconds`), formatted with the editable template; admin chooses which services appear and can switch Traffic OFF
Step 3 → Support sends the editable support text with URL buttons to the support username/group/channel from `settings`
Step 4 → Every one of these three has its text, buttons, links and on/off switch editable in admin/texts.php, admin/buttons.php and admin/settings.php

### Feature 5 — OTP Auto Delivery (cron.php):
Step 1 → cron.php runs every minute and loops about 55 seconds; every `check_interval` seconds it polls every active row in `api_providers` (success-otp-info endpoint) by priority, and also processes OTPs the admin adds manually for pool numbers
Step 2 → Normalize numbers to digits only and find the active owner in `numbers`
Step 3 → Dedupe with a unique hash of (number + sms text) in `otp_logs`
Step 4 → In one DB transaction with row locking: insert `otp_logs`, credit the user the service rate (fallback `otp_rate`), insert `transactions` with balance_after, update `user_stats`, mark the number status=used
Step 5 → Send the OTP to the user, then post to every matching active OTP group (Feature 6), then pay the referral bonus once on the referred user's first OTP
Step 6 → If a provider fails 3 times in a row, mark it down, switch to the next priority provider, and notify the admins once

### Feature 6 — OTP Group Broadcast (every OTP goes to the group):
Step 1 → `otp_groups` stores multiple groups/channels (title, chat_id, filter_service_id or NULL for all, mask_number, mask_otp, template_text, button_label, button_url, button_style, is_active)
Step 2 → Every successful OTP is posted automatically to all matching active groups
Step 3 → Mask options set by admin: number = none / partial (+88017****5678) / hidden; OTP = full / partial / hidden
Step 4 → Template is editable with placeholders {service} {emoji} {flag} {country} {number} {otp} {sms} {time} {bot_username} and includes an inline URL button to the bot
Step 5 → Failed sends retry 3 times and are logged in `activity_logs`; each group has a "Send Test Message" button and a pause toggle

### Feature 7 — Search OTP, 2FA Online and Profile:
Step 1 → Search OTP sets `state` = search_otp; user sends a number; check `otp_logs` first, then the provider search-otp endpoint, and show the latest OTP and SMS
Step 2 → 2FA Online sets `state` = twofa; user sends a Base32 secret; generate TOTP (30s, 6 digits, SHA1) in pure PHP; send the code with remaining seconds and a Refresh button; clear `state`
Step 3 → My Profile shows name, ID, balance, total numbers, total OTPs, total earned, referrals, join date, language, with buttons for Wallet, Withdraw, Language (all editable)

### Feature 8 — Wallet, Withdraw, Refer, Leaderboard:
Step 1 → Wallet shows balance, total OTPs, total earned, pending withdrawals, and a Withdraw button
Step 2 → Withdraw: choose from active `payment_methods` (admin-defined name, emoji, min, max, fee_percent, account_hint, daily_limit), enter account, enter amount; validate everything
Step 3 → Deduct balance immediately in a transaction, insert `withdrawals` status=pending, notify admins with Approve/Reject buttons
Step 4 → Approve marks paid (admin may add a transaction ID note) and notifies the user; Reject refunds with a reason and notifies the user
Step 5 → Refer shows the personal link, referral count, bonus per referral, and a Share button; Leaderboard shows the top 10 with period filter (today / week / all time); admin can disable either

### Feature 9 — Admin Web Panel (A to Z control):
Step 1 → **Dashboard**: total users, new today, active numbers, OTPs today, earnings paid today, pending withdrawals, pool stock per service, provider status, 7-day chart drawn with plain HTML/CSS
Step 2 → **Users and Balance**: search by ID/username/name; full profile with numbers, OTPs, transactions, referrals; ban/unban with reason; add, deduct or set balance with a required note (logged with the admin who did it); send a direct message; bulk add balance to all/selected users; export users as CSV
Step 3 → **Services, Ranges, Number Pool**: full CRUD for services (name, emoji, rate, daily limit, button color, order, active); ranges (country, flag, code, source api/pool, provider, order, active); number pool with single add, bulk paste (one number per line), CSV-style paste, delete, mark free/used/disabled, duplicate skip, stock counters
Step 4 → **API Providers**: add unlimited providers (name, base_url, api_key, key_header, paths for getnumber / search-otp / success-otp-info / liveaccess, field_map for response mapping, priority, is_active) with a "Test Connection" button and masked key display
Step 5 → **Texts, Buttons, Pages, Design**: edit every bot message in English and Bengali (welcome, banned, maintenance, captcha, service picker, range picker, number message, OTP message, proxy, traffic, support, profile, wallet, withdraw, referral, leaderboard, all errors, group template); edit all buttons and custom pages; edit panel colors, bot name, credit text, welcome photo
Step 6 → **Settings**: otp_rate, referral_bonus, min/max withdraw, max_active_numbers, number_expiry_minutes, cooldown_seconds, check_interval, liveaccess_cache_seconds, captcha_enabled, leaderboard_enabled, traffic_enabled, proxy_link, support_link, maintenance_mode, bot_username, credit_text, currency symbol
Step 7 → **Channels, OTP Groups, Broadcast**: CRUD for force-join channels and OTP groups; broadcast to all / active / by language with text, photo and inline URL buttons (with colors), run in batches by cron with live progress, pause and stop
Step 8 → **Withdrawals, Admins, Logs, Backup**: approve/reject with notes and filters; add/remove admins with roles (owner, manager, support) and per-page permission checkboxes; view `activity_logs` with filters; one-click SQL backup download of all tables

### Feature 10 — Admin Inside the Bot:
Step 1 → /admin works for Telegram IDs in the `admins` table (first owner from config.php)
Step 2 → Inline admin menu: stats, add balance, deduct balance, ban/unban, broadcast, add numbers to pool, toggle maintenance, toggle service/range/button/group, edit a text, view pending withdrawals
Step 3 → Add balance flow: send user ID, send amount, send note, confirm; the user receives a notification
Step 4 → Add numbers flow: choose service and range, paste numbers, confirm; show how many were added and how many duplicates were skipped
Step 5 → Every admin action is written to `activity_logs` with the admin ID


Create a complete android-compatible Android application named "SMS READER X"”.

The app is for a merchant’s own authorized Android device. Its purpose is to read payment transaction notification SMS with explicit user consent and send only non-sensitive transaction information to the merchant’s configured HTTPS payment-reconciliation API.

Important safety and privacy rules:
- Never secretly read or forward SMS.
- Never upload SMS automatically without clear user consent.
- Never transmit OTPs, PINs, passwords, login codes, card numbers, NID numbers, or authentication codes.
- Do not send all SMS messages. Process only transaction-notification messages from user-configured, approved sender IDs.
- Support manual review before sending each transaction during initial setup.
- Provide a visible background-service notification if any approved monitoring service is enabled.
- Include Start Monitoring and Stop Monitoring buttons.
- Use HTTPS only. Reject HTTP endpoints.
- Do not hide the app, service, notification, or data collection.
- Use fake sample SMS data for testing.

Core workflow:
1. User installs and opens the app.
2. Show a clear consent screen explaining:
   - Which SMS data will be read
   - Which sender IDs are allowed
   - Which API endpoint may receive the data
   - How the user can stop monitoring
3. Ask for the minimum necessary Android SMS permission.
4. User configures approved sender IDs manually, for example:
   - bKash
   - Nagad
   - Rocket
   - Upay
   - Other merchant-approved sender IDs
5. When a new SMS arrives:
   - Check whether the sender matches an approved sender ID.
   - Parse only transaction-related messages.
   - Ignore OTP, PIN, password, login, verification, and promotional messages.
   - Show the parsed result inside the app.
   - Add the transaction to a local Pending Transactions list.
6. The user reviews the parsed transaction.
7. Only after the user presses “Send to Gateway”, send the transaction to the configured API.
8. Show success, failure, retry, and local-save status.
9. Never retry forever and never send duplicate transactions.

D. API Settings
Allow the merchant to configure:
- HTTPS API URL
- POST method only
- Bearer token or API-key authentication
- Header name
- Secret value
- Merchant ID
- Terminal/device ID
- Request timeout
- Duplicate prevention setting
- JSON field mapping

Rules for API settings:
- Validate HTTPS URL.
- Store secrets using Android Keystore or encrypted storage.
- Never put secrets in URL query parameters.
- Never print secrets or SMS content in Logcat.
- Provide “Test API” using fake transaction data only.
- Show the endpoint domain clearly.
- Require confirmation before saving a new endpoint.

E. Sender and Parser Settings
- Add, edit, enable, and disable approved sender IDs.

- Configure separate parsing rules for each payment provider.
- Use regex or safe parsing rules to extract:
  - Transaction ID
  - Amount
  - Currency
  - Date/time
  - Customer reference
  - Balance, if present
- Do not treat balance as a payment amount.
- Add a parser preview using fake SMS examples.
- Include Bengali and English SMS examples.
- Add a confidence score.
- If parsing confidence is low, move the SMS to “Needs Review” instead of sending it.

F. Duplicate Protection
- Detect duplicate transaction IDs.
- Do not send the same transaction twice.
- Store a local hash of the transaction.
- Show duplicate warnings.
- Allow the merchant to manually override only after confirmation.

Before sending:

- Show fields that will be transmitted
- Show redacted values
